# Offline HTML evidence reader

Download a completed saved run with
`GET /runs/{run_id}/export?format=html`, then open the single file in a browser
without the API, network, model credentials, or the original corpus. Follow a
claim or final citation to its **exact frozen passage**, inspect the recorded
configuration and trace, and use browser-native Find, details, and Print.

This adds a presentation format to the existing validated `EvidenceExporter` /
`EvidenceBundle` path, not a frontend application or another retrieval pipeline.
JSON is still the default; existing JSON and Markdown content is unchanged.
Only completed, captured runs are exportable. Historical gaps are never filled
from today's documents or from a new model response.

![Measured synthetic offline HTML evidence reader](../assets/offline-evidence-reader.gif)

**GIF provenance:** a generated illustration from actual executed API output,
not a screen recording. The synthetic demo makes two original text ingests,
one fake-adapter query, and real downloads. It measures two frozen passages,
two final citations, six source links, zero network calls, and zero export-time
agent/corpus calls or event writes. Its HTML, JSON, and Markdown remain
byte-identical after the demo corpus is deleted and the application is restarted.
The fake answer is a placeholder, not a scientific finding or quality benchmark.

## 1. Run the isolated demonstration

From the repository root after installing the development extra:

```bash
uv sync --extra dev --locked
READER_DIR="$(mktemp -d)/offline-evidence-reader"
uv run --no-sync python -m scripts.demo_evidence_html --output-dir "$READER_DIR"
uv run --no-sync python -m scripts.create_evidence_html_gif \
  --transcript "$READER_DIR/transcript.txt" \
  --output "$READER_DIR/offline-evidence-reader.gif"
printf 'Open this local file in a browser: %s\n' "$READER_DIR/evidence.html"
```

Open the printed file, disconnect the browser from networking, and follow the
links under **Proposed references**, **Accepted by recorded grounding**, or
**Final recorded citations**. Source headings use frozen numeric ranks rather
than titles or raw IDs. Expand the recorded plan, request, and event details.
Use Print Preview; expand details first if your browser keeps closed disclosures
out of print. Essential answers, warnings, associations, and passages are visible
without expanding the operational trace.
The first Tab reveals **Skip to main content**; Enter follows the native fragment
link to the focusable main region, without JavaScript.

The demo uses the existing isolated `offline_settings` helper: environment,
dotenv, secret-file settings, and ambient provider keys are not read. Outbound
HTTP and socket connection attempts are guarded. It creates and removes only a
new temporary synthetic database, never the user's configured database. Export
guards fail on generation, retrieval, corpus reads/writes, or event appends.
No copyrighted papers, external services, or live inference are involved.

| Artifact inside the printed directory | Contents |
| --- | --- |
| `evidence.html` | Actual HTML response bytes, including fixed CSS and saved-file CSP |
| `evidence.json` / `evidence.md` | Existing formats of the same saved run |
| `restarted.html` | Actual byte-identical HTML after deleting the synthetic corpus and restarting |
| `checks.json` | Actual hashes, byte count, link count, CSP, restart comparisons and call/write counters |
| `transcript.txt` | Four measured panels consumed by the GIF renderer |
| `offline-evidence-reader.gif` | Optional illustration generated by the second command |

Both scripts refuse to overwrite existing named artifacts or dangling symlinks.
The GIF renderer reuses the existing Pillow development dependency and rejects
unrelated or clipped transcripts. Re-rendering the same transcript produces the
same four-frame GIF. Per-run IDs and timestamps in the evidence files are real;
reproducibility here means faithful rendering and unchanged saved-run exports,
not identical IDs for newly generated runs.

## 2. Download from the API

Use a trusted local API and an existing completed run ID. Discover saved IDs
through [run history](RUN_HISTORY_GUIDE.md); a recorded `DONE` state alone does
not guarantee that a legacy run has an evidence snapshot.

```bash
RUN_ID='replace-with-a-completed-run-uuid'
OUTPUT="$(mktemp -d)"
curl --fail-with-body --silent --show-error \
  "http://127.0.0.1:8000/runs/$RUN_ID/export?format=html" \
  --dump-header "$OUTPUT/headers.txt" --output "$OUTPUT/evidence.html"
```

Check the command's exit status before opening the file; an error response is
JSON, not a partial HTML report. The example uses a standard run UUID; URL-encode
custom run IDs as path components. For a separate synthetic API instance, use
the isolated settings/server instructions in the [Quickstart](../../QUICKSTART.md).
Do not expose an unauthenticated API or private artifact directory publicly.

| Request | Response |
| --- | --- |
| No `format`, or `format=json` | Existing version-1.0 `EvidenceBundle` JSON |
| `format=markdown` | Existing literal Markdown |
| `format=html` | `text/html; charset=utf-8`, self-contained semantic HTML |

Successful downloads retain `Cache-Control: no-store`,
`X-Content-Type-Options: nosniff`, and
`Content-Disposition: attachment; filename="evidence-<16 hex characters>.html"`.
The filename suffix is the first 16 hex characters of SHA-256 over the run ID;
it is **not** a signature or a digest of the whole HTML file. No title, source
path, URL, or raw run ID is interpolated into download headers.
OpenAPI advertises all three formats while retaining the JSON schema and default.

HTML also receives `Content-Security-Policy`. Both the response and the saved
file's early CSP metadata deny all resource loading by default, disallow base
URLs and form submission, and authorize only the fixed stylesheet's SHA-256:

```text
default-src 'none'; style-src 'sha256-<computed fixed CSS hash>';
base-uri 'none'; form-action 'none'
```

The HTTP header additionally disallows embedding with `frame-ancestors 'none'`;
that directive is not supported in a saved file's meta policy. There is no
`unsafe-inline` or `unsafe-eval`, JavaScript, remote CSS, image, font, form,
external hyperlink, or live API call. The renderer does not depend on CSP alone:
all captured text is escaped and every link is a generated local fragment.

## 3. Render in Python without constructing the application

Use the exporter against existing saved events, then call the pure renderer.
This example opens SQLite read-only and opts into the existing bounded event
reader; no `AppContainer`, corpus loading, provider, or settings are needed.

```python
import sqlite3
from contextlib import closing
from pathlib import Path

from agent.evidence_html import render_html
from storage.evidence_export import BoundedRunEvents, EvidenceExporter, EvidenceExportError

database = Path("/absolute/path/existing-runs.sqlite3").resolve(strict=True)
destination = Path("/absolute/path/new-evidence.html")
with closing(sqlite3.connect(database.as_uri() + "?mode=ro", uri=True)) as connection:
    connection.row_factory = sqlite3.Row
    connection.execute("BEGIN")
    encoding = connection.execute("PRAGMA encoding").fetchone()[0]
    bundle = EvidenceExporter(BoundedRunEvents(connection, encoding)).export(
        "replace-with-a-completed-run-uuid"
    )
    html = render_html(bundle)  # Raises EvidenceExportError; never truncates.
with destination.open("xb") as output:
    output.write(html.encode("utf-8"))
```

`render_html` accepts an **exporter-validated bundle**, does not mutate it, and
returns a Unicode string. It performs no I/O or clock reads. Arbitrarily
constructing/model-copying an `EvidenceBundle` is not a substitute for the
exporter's cross-record validation. Handle `EvidenceExportError.code` and
`.status_code` explicitly in callers; do not treat failures as empty evidence.
The optional `BoundedRunEvents` example additionally enforces its existing
100-event, 1 MiB per-event and 8 MiB total saved-read limits; those are distinct
from the HTML rendered-byte limit, and are not newly imposed on other exports.

## 4. What the reader preserves

| Reader area | Meaning and review boundary |
| --- | --- |
| Summary | Saved run/agent IDs, completion time, status, counts, provider/model, task type, context digest and warnings; no new export timestamp |
| Original question / recorded answer | Literal saved text and answer warnings, including the recorded ungrounded flag |
| Claim references | Separate proposed and accepted-by-recorded-grounding IDs in recorded order; missing IDs explicitly say **Unresolved reference** and have no link |
| Final citations | Saved title, document/chunk ID, short snippet and association, with a link to the full frozen passage when present |
| Frozen passages | Full captured text, final rank/score, retriever, path, document/chunk IDs, source string, metadata and text SHA-256 |
| Configuration | Recorded document scope, per-paper quota, minimum-document requirement, near-duplicate policy, effective runtime limits and capture limits |
| Expandable trace | Saved plan/rationale, exact provider-independent request, generation provenance and ordered events through the first terminal event |

`claim_evidence.evidence_ranks` can include **proposed** references that grounding
did not accept. The reader does not relabel this union as supporting evidence.
“Accepted” and a `grounded=true` flag record token-overlap processing, not
semantic entailment, study quality, independent evidence, or proof. A final
citation's snippet is not the complete passage; follow its numeric source link.
Unknown event payloads remain omitted with the existing `payload_omitted` flag
and warning. Hidden provider reasoning or arbitrary diagnostics are not added.

All dynamic strings, including Markdown, HTML, URL-like values, paths, IDs,
metadata and event types, remain **literal text**. They cannot become headings,
attributes, scripts, style, or navigation destinations. Anchors such as
`source-1` are generated from validated frozen ranks; claim/citation section
numbers are locally enumerated, never derived from untrusted identifiers.

### Whitespace and Unicode

Passage text is not normalized, reflowed into a new saved value, or clipped.
An inner `code` element protects leading newlines from HTML's `pre` handling;
carriage returns are escaped as character references so HTML input newline
normalization does not change them. Literal entity-looking strings are escaped
again rather than decoded as source markup. Wrapping is display-only.

Text blocks use `dir=auto`, `unicode-bidi: plaintext` and bounded wrapping.
Unicode, combining characters, and bidirectional controls remain in the text,
not silently removed or “cleaned.” These measures contain visual reordering;
they do not make spoofed identifiers trustworthy. Fonts, line wrapping, clipboard
behavior and printed output may differ by browser. The saved JSON and hashes
remain the machine-readable reference, not pixels on a screen.

NUL cannot round-trip in HTML, and unpaired surrogates cannot encode as UTF-8.
The renderer rejects unrepresentable literal text with an explicit error rather
than replacing it with a different passage. NUL remains inspectable in JSON.
Digests cover the original captured UTF-8 passage/context, not the escaped HTML,
rendered glyphs, complete paper, or every field in the record.

## 5. Limits and errors

HTML is limited to **4,194,304 rendered UTF-8 bytes (4 MiB)**, including escaped
text, all sections, metadata, duplicated operational content, and fixed markup
and CSS. Escaping `&` consumes five bytes, not one; multibyte text is counted by
encoded size, not character count. The limit is fixed, not a user-supplied
setting. Exact-limit output is accepted; any excess fails before a download is
returned. No sources, answer text, or trace entries are silently truncated.

Capture still has its independent version-one bounds: 50 passages, 262,144
context bytes, and 1,048,576 serialized snapshot bytes. A valid captured run
can nevertheless have too much answer/trace content for HTML. Keep JSON or
Markdown instead of pretending an incomplete HTML report is complete.

| HTTP status | `detail.code` | Meaning |
| --- | --- | --- |
| 404 | `run_not_found` | No saved events for this ID |
| 409 | `run_incomplete` / `run_failed` | No completed successful run |
| 409 | `snapshot_unavailable` | Legacy or uncaptured run; no reconstruction from current corpus |
| 409 | `invalid_run_record` | Inconsistent records, ranks, digests, sequence or unsupported version |
| 409 | `html_text_not_representable` | Literal text cannot be preserved faithfully in UTF-8 HTML |
| 413 | `html_export_too_large` | Full rendered HTML exceeds 4 MiB; no partial download |
| 422 | FastAPI validation response | Unsupported format; supported names are exactly `json`, `markdown`, `html` |

The existing exporter runs before rendering, so its errors keep their status
and detail codes. HTML-specific errors use the same JSON `detail.code` /
`detail.message` envelope, with `no-store` and `nosniff`, not an attachment.
JSON/Markdown behavior and the evidence schema are not changed.

## 6. Use cases, portfolio demonstration and boundaries

Use the file for an offline reading session, a permitted collaborator handoff,
or a printable engineering-review packet. A reviewer can move from a recorded
claim to a full passage without recreating an index or giving a browser model
credentials. Deleting current corpus rows does not erase retained snapshots;
new corpus contents and today's model settings cannot change this saved record.
Byte identity after restart assumes the same renderer version and saved events,
not a promise about future renderer releases or new LLM runs.

For a portfolio demo, run the synthetic script, show the real HTML and companion
JSON, explain proposed versus accepted references, and open the exact request.
Show the measured checks and byte-identical restarted file. Describe the
FastAPI/Pydantic/SQLite implementation, lexical hash-vector/BM25 retrieval,
lexical reranking, and hand-written Observe-Decide-Act state machine honestly.
This is not LangGraph or a learned semantic-embedding/cross-encoder demonstration.
The illustrated GIF is a navigation aid, not proof of application quality.

This feature is **not scientific validation, authentication, signed/tamper-proof
evidence, automatic redaction, an editable annotation UI, or another
retrieval/generation interface**. It does not attach later saved-answer reviews
or passage notes to the frozen bundle; those existing services are separate.
The API has no tenant boundary. Protect downloads, the event database and
backups. Source text, queries, metadata, answers and any secrets embedded in
them remain sensitive, even though application credentials are not exported.
Review content and rights before sharing; CSP is not a privacy filter.

### Recorded identity versus current provider catalogs

Reader labels come only from saved generation records. A missing model remains
“Not recorded”; no current default is substituted or retrospectively verified.
The **2026-10-06 America/Los_Angeles** documentation-only check still selects
GPT-6 Astra, Claude Sonnet 5.5, Gemini 3.8 Flash and Kimi K3 in this repository.
OpenAI additionally lists 6.1 Sol as a balance choice and Luna for cost-sensitive
work; Anthropic's general Opus 5.5 recommendation does not change our Sonnet
choice. See the source-linked [provider guide](PROVIDER_MODELS_GUIDE.md).
This is not a live inference, entitlement, latency or accuracy test, and does
not change separately dated migration checks, defaults or routing.

## 7. Workflow inspiration and attribution

Public primary references checked by the daily maintenance run on
**2026-10-06 America/Los_Angeles**:

- [Zotero reports](https://www.zotero.org/support/reports) describes saveable,
  printable HTML reports for research metadata and notes. That workflow informs
  the single-file, browser-native review format, not a Zotero-format integration.
- [RAGFlow, Grounded citations](https://github.com/infiniflow/ragflow)
  describes quick reference views and traceable citations. This reader instead
  resolves only its already frozen local IDs; it does not adopt RAGFlow's UI or
  claim the same retrieval or parsing capabilities.
- [PaperQA](https://github.com/Future-House/paper-qa) describes grounded answers,
  in-text references and saved answers. It informs the review workflow, not a
  claim of comparable answer quality or scientific verification.

These are workflow precedents, not claims of feature parity, competitor
deficiencies, or copied implementation/documentation. The concrete repository
gap was an offline linked HTML view alongside existing JSON/Markdown exports.
